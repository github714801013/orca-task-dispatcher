# 分发最后一跳改为普通 Orca 终端投递

2026-09-17，orca-task-dispatcher 把分发的最后一跳从 Orca 的受监督 worker 改为普通终端投递，并停止使用编排 Run。`launch` 对每个任务按顺序执行：① 确保源仓库已在 Orca 注册 → ② `orca worktree create --name <任务编号>-<语义slug> --repo id:<repoId> --base-branch <base_branch> --no-parent --comment orca-task-dispatcher:<assignment_id> --json`（不带 `--agent`，不传 `--prompt`）→ ③ `git branch -m <用户名>/<工作区名>` → ④ 复用 dev-spec-gen 的 `--sync-only` 入口同步未托管内容与 IDE 配置 → ⑤ 把源仓库 `.runtime/<task-id>/docs/engineering/` 下的暂存制品迁入工作区并校验 → ⑥ `orca terminal create --worktree id:<worktreeId> --title <工作区名> --command claude` → ⑦ `orca terminal wait --terminal <handle> --for tui-idle --timeout-ms 120000` → ⑧ `orca terminal send --terminal <handle> --text "<command_template 渲染结果>" --enter --wait-submit 10 --json`。接收方是独立 Claude 会话，分发会话在确认投递回执后结束本轮。

- **Status**: accepted（取代 [0004](0004-task-worktree-created-by-orca-and-dispatched-as-supervised-worker.md) 中 `worker-start` 的部分；工作区由 Orca 创建、制品迁入校验、稳定工作区命名与归属校验仍然有效）
- **Considered Options**: 维持 `orca orchestration worker-start` 的受监督 worker——放弃：接收方会被 Orca 注入协调者协议（`worker_done`/`ask`），而分发会话不进入监督循环，协议前导与流程模板叠加在同一段文本里，且每次分发都要先 `run-create`/`run-use` 绑定 Run；用 `orca worktree create --agent claude --prompt` 一步完成建区与会话启动——放弃：同步未托管文件与迁移制品必须发生在会话开始之前，一步式没有插入点；复用既有工作区里已有的 Claude 终端——放弃：既有终端可能已收到监督前导或人工输入，无法证明其身份干净，也无法区分「本次投递」与「上次残留」。
- **Consequences**: 分发结果按回执判定而非按 CLI 顶层 `ok`：`send.accepted` 证明输入被接受，`send.prompt.stages` 含 `turn_started` 才证明观察到本轮起步。仅接受未起步仍记 `dispatched` 并保留「未观察到起步」告警；主机返回 `observation=unsupported`（旧 host 无耐久回执）或回执结构不合法时转人工复位，不重发。`--wait-submit` 只观察已接受的输入，观察期静默不构成重发理由，因此没有自动重试；发送前后的资源与请求标识（`terminal_handle`、`send_request_id`）在发送前落盘，进程中断后 `recover` 能区分「未发送」与「发送结果未知」，只做只读核对、不重发。终端就绪由 `terminal wait --for tui-idle` 判定，未就绪时只创建终端不发送文本。删除 `worker_start`、`workers`、`orchestration_run_create/use/show`、`ensure_orchestration_run` 与 `.runtime/orchestration.json`；调度之外的占用保护仍在：工作区内存在活动开发会话时不复用、不清理自动后缀工作区，只读探测失败按占用处理。历史状态里带旧 `dispatch_id` 的记录只报告并转人工复位，不迁移、不重发；`.runtime/orchestration.json` 与既有 Run 保持不动。`terminal create` 不带 `--focus`：首次创建同时打开 workspace 并聚焦会句柄超时，需要前台时由人工或后续 `terminal switch` 完成。
