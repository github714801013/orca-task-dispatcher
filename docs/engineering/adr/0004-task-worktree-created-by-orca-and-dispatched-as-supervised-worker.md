# 任务工作区改由 Orca 创建，分发改用受监督 worker

2026-09-16，orca-task-dispatcher 把任务工作区的创建从 dev-spec-gen 的 worktree CLI 移交给 Orca，并把分发的最后一跳从「自建终端后发送命令」改为 Orca 的受监督 worker。`launch` 对每个任务按顺序执行：① 确保源仓库已在 Orca 注册（按路径在 `orca repo list` 结果中查找，未命中时 `orca repo add --path` 后重查一次）→ ② `orca worktree create --name <任务编号>-<语义slug> --repo id:<repoId> --base-branch <base_branch> --no-parent --json` → ③ `git branch -m <用户名>/<工作区名>` → ④ 复用 dev-spec-gen 的 `--sync-only` 入口同步未托管内容与 IDE 配置 → ⑤ 把源仓库 `.runtime/<task-id>/docs/engineering/` 下的暂存制品迁入工作区并校验 → ⑥ `orca orchestration worker-start --worktree id:<worktreeId> --agent claude --spec "<command_template>" --task-title <标题>`。dev-spec-gen 不再创建工作区。

- **Status**: superseded by [0005](0005-last-hop-uses-plain-orca-terminal-delivery.md)（本文描述的分发方式已不再使用；工作区由 Orca 创建、稳定工作区命名与归属校验、制品迁入校验仍然有效）
- **Considered Options**: 维持现状（dev-spec-gen worktree CLI 创建 + dispatcher 自建终端并发送）——放弃：外部创建的工作区在 Orca 侧是「未装载」的，首次创建终端会句柄超时，需要一整套装载与残留回收补救，且创建、路径校验、复用判定都散落在另一个仓库；`orca worktree create --agent claude --prompt` 一步完成建工作区、起终端与发任务——放弃：同步未托管文件与修补 IDE 必须发生在 agent 启动之前，一步式没有插入点；让会话先建工作区、`launch` 只启动 worker——放弃：工作区创建与制品迁移必须共享同一份路径事实，拆开会把路径重新变成需要人工确认的输入。
- **Consequences**: 工作区由 Orca 自己创建，天然处于已装载状态，装载超时与残留回收的问题不再存在，上一版为此引入的终端重试、就绪等待、preview 校验与发送重试一并删除。工作区位置由 Orca 决定（`<Orca workspaceDir>/<仓库名>/<工作区名>`），配置化的 `workspace.worktrees_root` 与按路径解析外部 worktree 的逻辑被删除；`--name` 同时决定目录名与初始分支名，因此目录名只能是 `<任务编号>-<语义slug>`，无法再由调用方给出完整路径。启动命令与权限参数改由 Orca 启动器决定，`dispatch.agent_commands`、`dispatch.agent_extra_args` 以及为其预写 `skipDangerousModePermissionPrompt` 的兜底逻辑作废。分发结果只按 CLI 的 `ok` 判定，`state`/`stage` 里的 `outcome_unknown` 与 `turn_start_unobserved` 表示 Orca 未观察到 worker 起步，不等同失败；`recover` 改为按状态里的 `dispatch_id` 调 `worker-show` 复核。`worker-start` 要求调用方绑定编排 Run，Dispatcher 因此会在首次调用时 `run-create` 一次并把 `runId` 记入 `.runtime/orchestration.json`。跨仓库部分：dev-spec-gen 需要新增 `--sync-only` 入口。未注册到 Orca 的源仓库必须先 `orca repo add --path <源仓库>`，否则所有 Orca 命令都返回 `repo_not_found`。
